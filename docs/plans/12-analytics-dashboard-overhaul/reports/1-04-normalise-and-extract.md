## Departures and judgement calls
- The brief says usage events are `transcript.assistant_message` for all harnesses and also that other assistant messages are `assistant_message`. I read that as payload-based: `usage` when a usage/tokens object is present, so Codex `transcript.assistant_message` (no tokens) is `assistant_message`. Unit 1-05 should not assume every assistant_message is non-usage.
- `StopFailure`, `message.part.updated` and `experimental.text.complete` mapping choices go beyond the brief's seed; they are my reading of the DESIGN value list.
- `Model` is extracted on every Codex/Claude/OpenCode `transcript.*` event with a model, including Codex `transcript.assistant_message` (no tokens). It is empty on tool events even where the payload has `model`.
- The fixture is larger than the 150-line estimate (indent=1 JSON, one field per line).

## Gap in the design table
DESIGN's OpenCode row lists only model and cost, but the payload carries `tokens.{input,output,reasoning,cache.read,cache.write}`. These are extracted into the same columns, since Phase 1's outcome needs token columns per harness. The design table should be amended.
