# Jev research methodology — active path

**Status:** research design, 2026-10-02. No Jev decision policy is empirically established or authorised for runtime use. **Parent:** [hypotheses](JEV-HYPOTHESES.md). **Human wording:** [provenance](PROVENANCE-jev-hypotheses-2026-10-02.md).

The reusable research loop, including early failed tests and evidence-backed white papers, lives in the [`white-paper` skill](../../plugins/workflow-lab/skills/white-paper/SKILL.md). Older Jev packs retain their data, failed trials, and protocols as evidence history. Where their proposed next step conflicts with this file, use this study design and record the discrepancy.

## Jev-specific evidence requirements

1. **Name the decision and counterfactual.** For each proposed use, write the exact input available at decision time, the Jev answer, the deterministic checks, the action it could change, and what the current workflow would have done. Record separately *advice*, *action taken*, and *downstream outcome*.
2. **Build a case manifest.** Identify source run, project, harness, task type, artifact version, checkpoint, outcome, and eligibility. Keep all checkpoints from one session and closely related plans in the same data split. Record missing or censored outcomes. Never use later transcript content in an input snapshot or matcher label.
3. **Establish reference outcomes independent of Jev.** Use deliverables, verifiers, later edits/reviews, and a written human or blinded analyst rubric. Adjudicate disagreement. Model agreement alone is a diagnostic; it is not the final quality reference. Preserve ambiguous cases rather than forcing a positive label.
4. **Separate four questions:** Is the proposed signal or criterion associated with the outcome? Can Jev read it from affordable state? Does a decision rule improve choices on held-out cases? Does acting on that rule improve quality and net cost in a prospective or controlled comparison? Passing an earlier question does not answer a later one.
5. **Compare against cheap baselines.** Include the current workflow, deterministic facts and simple rules, and a Jev-free turn or file-scope heuristic where appropriate. Count all Jev calls, larger state, retries, reviewer effort, compaction/handoff cost, and rework. Report savings per successful deliverable as well as raw call or turn counts.
6. **Count independent cases.** Explore many input and wording variants with recorded spend, but group all checkpoints from one session and related plans when evaluating a selected policy. Large numbers of calls over the same small corpus are correlated trials, not independent cases.

Use an evidence ledger for every experiment: `case_id`, source/hash, split, decision point or checkpoint, snapshot specification/hash, question and model version, raw response, parse failure, independent labels, action under each rule, eventual outcome, provider cost, and adjudication notes. Publish denominators and uncertainty at the **plan or session level**, including by task/harness where the sample allows. Report false confident actions and concrete failure cases, not only a chosen threshold's average score.

## H1 — phase-boundary decisions

Study **design exit, refine exit, and build exit separately**. The unit is a real plan/phase/brief at the moment its current gate would run. A small plan corpus makes this a case-level study first; do not create a large apparent sample by asking many phrasings of the same few plans.

| Gate | Jev measurement to try | Candidate action and reference outcome |
|---|---|---|
| Design exit | Separate plain-language yes/no criteria with confidence: problem addressed; phase outcomes measurable, well defined, and justified; stated acceptance/brief criteria likewise where they exist. Missing criteria are not affirmative evidence. | High-confidence, complete criteria may support advance; a specific high-confidence gap may send design back for correction. Compare with later refine/build discoveries, design changes, and independent outcome assessment. Preserve existing structural asserts. |
| Refine exit | Continuous per-brief size estimate plus expected file scope, with confidence or explicit unknowns. Do not ask only “is this rightsized?” | Rank briefs for further refinement/review. Test the **reviews safely avoided**, not just the briefs selected for attention. Compare predicted scope/size with actual files, effort, dependencies, review findings, and later rework. |
| Build exit | Criterion-by-criterion assessment of phase outcome and evidence, including unresolved exceptions, with confidence. | Advance, correct, or request review only where evidence supports that choice. Compare with verifier results, independent review yield, downstream defects, and phase outcome quality. A skipped review counts as saved work only if its later defect/rework cost is included. |

Start with the current workflow as the default on low confidence, missing state, parse failure, or disagreement with a deterministic failure. Define **action-specific** high-confidence requirements before examining held-out cases. Evaluate the *precision and harm* of actions Jev would actually change; low coverage is acceptable. For a proposed skip or advance, estimate false confident decisions and downstream cost, then compare avoided agent work with Jev cost. No universal probability threshold or acceptable false-positive rate is known yet. If the corpus is too small to bound a harmful action, keep the result exploratory and gather more cases rather than interpreting many matcher trials as validation.

**Work order:** inventory completed plans and reconstruct gate-time snapshots → write criterion and outcome rubrics → blind case assessment and baseline decisions → try a small, declared Jev question set → inspect false confident cases and calibrate a conservative action rule on development cases → evaluate it on held-out plans → shadow decisions on new runs → controlled action trial when quality risk is understood. Report each gate separately before a whole-workflow claim.

## H2 — session continuation near the cost crossover

Start the first candidate observation at **60 assistant turns**, with repeated looks around **15 turns** apart (60, 75, 90, …). This reflects Cody's working ideal of about 50 turns or fewer and allows a decision before the previously noted 75-turn cost concern. These are trial points, not a proven optimum or a hard stop. A transcript ending soon is not necessarily useful completion; a long session is not necessarily waste. The outcome is useful completion with acceptable quality and total cost, judged from work evidence. Claude Code lengths use deduplicated assistant API calls. Cursor JSONL lengths use observed parent assistant message rows: each row is a continuation turn, but the format does not certify billable API calls. Cursor cloud runs (`bc-*` IDs) require separate extraction before they can join this cohort.

1. **Discover candidate signals.** Qualitative analysts inspect complete sessions and propose an inventory. For each signal record task applicability, observable anchor, counterexamples, proposed direction (near useful completion, productive continuation, or prolonged low-value work), and what a zero-call rule can already detect. “Tests passed” is an example to test, not an accepted predictor. Discovery cases cannot validate their own proposed signals.
2. **Test predictive association before Jev.** On separate sessions, construct prefix-only snapshots at fixed checkpoints. Label signal presence independently of Jev and label subsequent useful completion within predeclared horizons (for example 15/30 turns), prolonged continuation, quality, and censoring. Compare outcome rates when each signal is present versus absent against the checkpoint/task baseline. Include uncertainty, coverage, calibration by task type, and counterexamples. Reject signals with no useful incremental association beyond cheap facts. Avoid selecting only sessions already known to exceed 60 without accounting for that selection.
3. **Test Jev as a matcher.** For supported signals, vary matcher language and bounded input-state subsets. Compare Jev's per-signal confidence with independent presence labels, including ambiguous examples, and then verify that its measured score retains the signal's outcome association. Try cheap programmatic state first when it carries the fact; richer state earns its cost by improved held-out performance. Track state size, parse/missing rate, latency, and actual price. Many wording/state calls can be useful for tuning, but the number of independent sessions remains the evidence denominator.
4. **Combine and replay.** Build the continuation-confidence bar outside Jev using only signals that survived the earlier stages. Specify weights or rule, handling of missing scores, first checkpoint, repeated ~15-turn checks, modest per-round discount, and whether new evidence can restore confidence. Tune on development sessions; replay once on held-out sessions. Compare with no intervention, a turn rule, deterministic profiles, and older stop-confidence proposals. Distinguish the decision *continue briefly* from the later choice *close, compact, or hand off*. Offline replay estimates what advice would have been given; it cannot show how the agent would respond to changed instructions.
5. **Test the intervention.** Run in shadow first, then a controlled live trial if replay supports it. Measure premature interruption, productive extra turns preserved, low-value turns avoided, final deliverable quality, successful completion, rework, and **total provider cost per successful deliverable**. Include Jev and handoff costs. Segment by task type and harness; report where the signal set does not transfer.

The previous `A0` exact-exit agreement failure (α = 0.1189 on its initial panel) is evidence against that *gold protocol*, not against every signal or this continuation-confidence hypothesis. The prior shape panels and wave trials are useful discovery material and failure cases. They do not substitute for independent signal-outcome association or intervention results.

### H2 track B — hook-event state

Same evidence rules as H2 steps 1-5; what changes is the **input representation and cadence**. Treat it as a competing arm, not a replacement, until it beats or complements transcript-prefix state on held-out sessions.

1. **Fix the hook-state spec.** Define exactly what `UserPromptSubmit` and `PostToolBatch` deliver and what each state variant keeps (last N batches, all prompts, counters). Hash each spec. Verify historical Claude transcripts can reproduce it prefix-only, and note the Cursor and OpenCode gap (no hooks; replay from transcripts only).
2. **Re-derive signals under the limit.** Per H2 step 1, but only from signals visible without tool output. Record which transcript-based candidates are lost (result-dependent ones) and which new ones appear (prompt cadence, repeated targets, tool mix, user redirection).
3. **Association before Jev.** Test each signal's link to later useful completion on separate sessions, against the turn-count and cheap-counter baselines. A signal that adds nothing over counters does not need Jev.
4. **Cadence trials.** Compare checkpoint spacing (for example every batch, every 5, every 15 turns) and window sizes. More calls on the same sessions are correlated trials; meter total Jev cost per session, since frequent cheap calls can exceed one larger call.
5. **Head-to-head.** Against track A state at the same checkpoints and against no-Jev rules: held-out signal accuracy, outcome association, premature-interruption rate, and cost per successful deliverable.
